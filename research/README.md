## 0. 阅读入口与适用范围

1. **AGENTS.md** — 此研究目录内的 AI 执行规则、证据与变更边界。
2. **BASELINE.md** — 已核实的仓库快照、原始资料入口、未知与冲突。
3. **PLAN.md** — 研究主线、阶段、状态和可验证交付。
4. **METHOD.md** — 文档分类、术语、标准对应、取证和质量检查。
5. **TEMPLATES.md** — 报告、机制研究、调用链、对照和评审的最小格式。

上游根目录 AGENTS.md、ARCHITECTURE.md、docs/、content/docs/、源码及测试等是**研究对象和原始证据**。上游关于“如何开发 ObjectStack”的指令，不自动成为“如何研究 ObjectStack”的管理规范。研究只在 research/ 下生成和修改成果；需要修上游程序时另开独立任务、分支和审查。

## 1. 总目标

以系统工程、软件工程、成熟实践及有边界的国际标准为参照，恢复 ObjectStack 的系统定位、产品与功能、业务与角色、系统及程序架构、运行行为、质量与演进；从源码、测试、文档、问题记录及必要的运行实验验证事实；与 Java 生态和现有 DES-ARC/前后端架构双向批判比较。

**学习与工程使用并重**：理解是什么、为什么、如何成立、在哪里与何时适用、实现细节、限制与反例；只把经过验证且能改善工程产物的知识带回现有体系。

## 3. 信息路线

官方文档/源码/示例/测试/Issue/ADR/Commit/运行记录 → 来源与版本定位 → 实现路径和反例 → 事实/推断/未知区分 → 机制与适用性论证 → 原则与设计比较 → 工程采用/不采用的理由。
