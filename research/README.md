## 0. 阅读入口与适用范围

1. **DESIGN.md** — 研究总体设计：知识对象/关系、专业深度、双路研究、成果消费和重大设计决定。
2. **PLAN.md** — **当前唯一执行接续入口**：阶段事实、下一批工作、完成与未完成、恢复点。
3. **BASELINE.md** — 源码与外部资料固定版本、出处、证据界限和重要冲突。
4. **AGENTS.md** — AI 研究指令、开始/结束/偏差处理和真实状态约束。
5. **METHOD.md** — 专业内容类别、证据分级、历史因果及质量要求。
6. **TEMPLATES.md** — 研究报告、机制、源码链、知识候选与工程消费格式。

**中断恢复**：先读本入口、DESIGN.md §10 当前判断、PLAN.md §六接续记录、BASELINE.md 当前快照；再按 PLAN 的下一批定位需要的源码和研究成果。Git 中的这些信息是可复核的工作记忆，不能以聊天记忆替代。

上游根目录 AGENTS.md、ARCHITECTURE.md、docs/、content/docs/、源码及测试等是**研究对象和原始证据**。上游关于“如何开发 ObjectStack”的指令，不自动成为“如何研究 ObjectStack”的管理规范。研究只在 research/ 下生成和修改成果；需要修上游程序时另开独立任务、分支和审查。

## 1. 总目标

以系统工程、软件工程、成熟实践及有边界的国际标准为参照，恢复 ObjectStack 的系统定位、产品与功能、业务与角色、系统及程序架构、运行行为、质量与演进；从源码、测试、文档、问题记录及必要的运行实验验证事实；与 Java 生态和现有 DES-ARC/前后端架构双向批判比较。

**学习与工程使用并重**：理解是什么、为什么、如何成立、在哪里与何时适用、实现细节、限制与反例；只把经过验证且能改善工程产物的知识带回现有体系。

## 3. 研究成果和实际知识资产的关系

六项报告用于完整理解和对比；业务规则、术语、契约、程序机制、历史失败、测试方法及工具等可形成**可独立定位的知识候选**。研究深入与知识提取同步推进，只有目标任务使用、验证后才能称为“已采用/实际有效”。知识未必都要成为 Skill、规则或代码包。详细对象、使用路径和维护源以 DESIGN.md §2–§8 为准；资源模板见 TEMPLATES.md。

## 4. 信息路线

官方文档/源码/示例/测试/Issue/ADR/Commit/运行记录 → 来源与版本定位 → 实现路径和反例 → 事实/推断/未知区分 → 机制与适用性论证 → 原则与设计比较 → 工程采用/不采用的理由。

研究的首要对象是 **当前 Fork 固定快照**；上游更新另立比较记录，不得静默混入同一结论。外部 HotCRM、ObjectStack Docs 等不是本 Fork 自带的全部来源，需分别标记版本和范围。
